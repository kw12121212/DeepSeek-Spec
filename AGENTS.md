# AGENTS.md — DeepSeek-Spec

Guidance for AI coding agents working on this codebase.

## Project

DeepSeek-Spec is a DeepSeek-native coding agent with a cache-first loop. TypeScript 5.6+, ESM, strict mode. Ink 5 + React for the TUI. Vitest for tests. Biome for lint/format. Bun is the runtime and package manager — use `bun` (not `npm`, not `npx`) for all commands. Node >=22.

## Architecture

Four design pillars — understand these before touching core modules:

1. **Cache-First Loop** (`src/loop/`, `src/core/`) — Immutable prefix, append-only log, volatile scratch. Edits that mutate earlier messages break the DeepSeek prefix cache.
2. **Tool-Call Repair** (`src/repair/`) — Multi-pass pipeline: flatten -> scavenge -> truncation -> storm.
3. **Cost Control** (`src/loop/`) — Flash-first defaults, turn-end compaction, model selection.
4. **Self-Report Escalation** — `<<<NEEDS_PRO>>>` marker for tier escalation.

## Code Conventions

### Comments — default is none

Write a comment ONLY to explain a non-obvious **why**. Never explain **what** — names say it.

Don't write:
- What the code does
- Module-level essays / multi-paragraph docstrings
- Conversation history ("user reported X", "v0.13 introduced Z")
- Section banners (`// --- helpers ---`)
- Restated parameter docs

If a comment is justified, one line is enough. Comments needing 4+ lines mean the code needs to be clearer first.

### TypeScript

- Strict mode. No `any` without `// biome-ignore` and a reason.
- `import type` for type-only imports (Biome `useImportType: warn`).
- Named exports only. No `export default`.
- No barrel `index.ts` re-exports unless they meaningfully shrink the public surface.

### Style

- 2-space indent, double quotes, semicolons always, 100-char line width
- Trailing commas everywhere
- Biome handles formatting — run `bun run lint:fix` before committing

### Files

- One responsibility per file
- File header comment: zero or one line
- No new `*.md` files unless explicitly asked

### Errors

- No try/catch for internal errors. Trust your own code.
- No validation the type system already proves.
- Boundary code (user input, network, FS) does validate.
- Log + crash > silent wrong output.

### Tests

- Test invariants, edge cases, regressions — not type signatures
- Don't write tests just to bump coverage
- Flat `*.test.ts` in `tests/`, named after the module they test
- Comment policy is enforced by `tests/comment-policy.test.ts`

### Git

- Imperative mood, scope tag, why-not-what: `feat(ui): ...`, `fix(loop): ...`
- One logical change per commit
- No `Co-Authored-By: Claude` trailer
- Don't touch `CHANGELOG.md`

## Critical Warnings

- **This IS DeepSeek-Spec** — edits to `src/loop/`, `src/repair/`, `src/tools/`, `src/mcp/` affect every session. Test before publishing.
- **SEARCH must match byte-for-byte** — the edit gate in `src/code/edit-blocks.ts` enforces exact match. Trailing whitespace or wrong indent = mismatch.
- **`dist/`** is generated by tsup. Never hand-edit.
- **`.dspec/semantic/`** is auto-generated. Never hand-edit.
- **Prefix cache stability** — any change that mutates earlier messages in the event log breaks the DeepSeek prefix cache invariant.

## Libraries to use (not hand-roll)

- Visual width / unicode width -> `string-width`
- Grapheme segmentation -> `Intl.Segmenter`
- ANSI strip -> `string-width` internals
- Color -> `theme.ts` constants, not raw hex

## Pre-push

`bun run verify` must pass (lint + typecheck + test + comment-policy gate).
